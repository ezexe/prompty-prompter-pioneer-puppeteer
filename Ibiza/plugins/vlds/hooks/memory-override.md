## VLDS memory override (always active)

**The built-in memory system is the base class; VLDS extends it.**
`base.read()` and `base.write()` run untouched, exactly as the system's own `# Memory` instructions define them — then this layer applies on top, the way a virtual method's override wraps its base.

`store` = **`<working dir>/.claude/vlds/`** — the working directory attached to this session, never a hardcoded machine path.
Neither `.claude/` nor `vlds/` need pre-exist; the first Write creates them.

### These fire. Act on them.

| Fires when | Do |
|---|---|
| **a message arrives, before you answer it** | the prompt hook stamped its row in **`store/dispatch.md`** — fingerprint, time, arrival — and ran the mechanical half of the dispatch barrier: no earlier row resembles the message → it wrote `state: FRESH`, answer; an earlier row resembles it → it named the candidate and left `state:` open → hand the message to the operator (open) before answering and act on its derivation: FRESH → answer; ECHO → answer the delta, never the message again; SUPERSEDED → surface the free instead of acting. `addressed:` (with `match:` / `freed-by:`) is the operator's at the turn's close. A task notification — a background task's completion delivered as a prompt, the operator's own among them — is never an ask: the hook stamps its row complete on arrival, and nothing is owed for it. No hook output → the stamp is the operator's too, from the message and the latest `now:` |
| session starts, or stored state is about to steer work | the hooks have done the mechanical half: the SessionStart hooks injected this contract, a digest of `store/phi-index.md`, one digest line per hot file, the owner voice, and the check's verdict — and NOT the hot files: **recall is pooled**, by the operator. At the first prompt, derive its task in one line and launch the operator (open) as the SessionStart directive says (the Agent tool; its brief is the plugin's `hooks/operator-prompt.md`, and the pool's is `hooks/pool-prompt.md`; the prompt hook's first-prompt line repeats the ask). Its derivation carries the pool — the store read whole, every entry through the gc read barrier, pooled into one informed response scoped to that task, at most 8,000 characters — which is the recall, pulled into this context in place of the files; the operator also writes `store/recall-pool.md`, which a compact re-injects. Never open a hot file here — when the pool's line on an entry is not enough to steer, ask the operator for the entry, not the file; never `store/arc/` or a masked span; every pooled item still passes the read barrier: freed, stale, or unowned → surface it, do not apply it. The prompt hook poured `store/dispatch.md` whole-file into `store/arc/` on a new session's first prompt (a resume, fork, or compact pours nothing — its entries are its own). `pool: inject` in the index's `## recall` section restores the slot injection of every inject file, chunked under the harness's 10,000-character cap. The judged sweep — which ruling is spent, which claim is stale, which correction's lesson is doctrine now, where a pour lands when no count opens one position — is the operator's sweep moment, launched whenever the check shows it owed, never held for the word; the light classes settle at every turn's close on their own. No Agent tool, or no injection at all → the degraded path: read `store/phi-index.md` and the hot files yourself (no index yet → cold-start on `store/*`), and say so |
| **the message is short, typo'd, or truncated** | a known short command — one the store's owner corpus already holds, which the prompt hook says so of, printing how often and what was done the last time — is derived from that line, mechanically, no operator; an unknown one goes to the operator (open), which derives its intent from the nearest prior derivation in `store/dispatch.md`, then `store/local-storage.md`, the `### owner voice` digest being the mechanical head of that corpus, and completes a truncated tail from the sentence's own verb; act on the derivation before asking, and state it in ONE line at the top of the reply, never as a footnote at the bottom |
| **a follow-up quotes the prior reply back, or opens with a correction of its reading** ("should have just been", "i meant", "incorrect interpretation") | it is a correction of the reading, not a new task: re-read the prior message under the new derivation, re-emit the deliverable in the named form, and hand the operator (close) the `correction` — `match` against `meant` — for `store/ledger.md`; do not add a second deliverable beside the wrong one |
| the user rules, prefers, corrects, or retracts | hand the operator (close) their verbatim words (and where a deliverable goes, for `form:`); it appends to `store/local-storage.md` — and on a retraction sweeps what the free reaches and appends to `store/tombstones.md` |
| a claim is verified against a source | hand the operator (close) the claim and what was read; it appends to `store/data-store.md` — re-verified on recall, since verification decays as the world drifts |
| an inference is minted that the work leans on | hand the operator (close) the inference and its basis; it appends to `store/virtual.md`, where the entry expires at turn end unless promoted |
| a task starts, moves, or completes | hand the operator (close) where it stands; it appends to `store/session-storage.md`, and completion clears its entries |
| the guide settles a rule, or reuses one | hand the operator (close) the rule and the match; it writes `store/index.md` (the rule) and `store/ledger.md` (the event, with the match that justified it) |
| **a reading that steered work turns out to be wrong** | hand the operator (close) the `correction` — `match` (what was assumed) against `meant` (what was wanted), and the fix — for `store/ledger.md`, **in the turn it is caught**: the dispatch record dies with its session and is collected unread, so a lesson left there is lost — and by the time anything collects it, the only party who could judge what deserved keeping is gone |
| the looper runs an instrument | hand the operator (close) that decision, tagged; it appends to `store/logger.md` |
| **the turn closes** — before the closing statement | write the turn's record — one `## <file>` block per entry the rows above owe, each in its file's own shape with the facts only this context holds, and one block per message row (its fingerprint's opening as the head, the fields to add) — to the notebook, and run the plugin's `scripts/record.py` on it (`--store`, `--session`, `--now` the latest `now:`, `--record` the path); it appends, completes the rows, runs the check, and prints the close derivation — the entries written, the rows completed, anything refused and why, the verdict, what is owed — which you carry into the closing: the line that named it before, one line on what was written after. No judgment is spent on a close; a refused block is rewritten and the record re-run |

**The floor.** A session that ends with its dispatch rows stamped but never completed did not run this layer.
The stamp is the hook's on every message; `state: FRESH` is the hook's when no earlier row resembles the message; the rest is the operator's — so a row still open when the next session's first prompt pours the record is a turn whose close never ran, and leaving every row that way is the one outcome that is always wrong.
Do not wait to be asked; a store is built by the turns that pass through it.
**The operator.** Every VLDS operation that needs judgment runs in a subagent — the operator — never in this context: the store's bytes are read and written there, and what returns is a derivation, the one thing this context acts on; what needs no judgment runs in a script, for nothing. Two judged moments. Open, before answering — when the prompt hook names a candidate row, calls a short message unknown, or says the pool is not yet built: its derivation is the barrier's state and match, the intent in one line, and at the first prompt the pool (on the index's `pool-model:`, sonnet by default — the one judged read a whole session leans on; the rest of open on `operator-model:`, haiku by default). Sweep, whenever the check shows judged debt: it scores what is cold and names the entries by head line, and the plugin's `scripts/normalize.py --pour` places them on the register (on `sweep-model:`, sonnet by default). The close is mechanical — the record script's, per the table — and a known short command is derived by the prompt hook. The Agent tool launches the operator once per session, at the first moment, in the foreground (subagent_type general-purpose) with one message: read the plugin's `hooks/operator-prompt.md`, then store, session, the latest `now:`, the moment, and the facts only this context holds — the message and its stamp, the user's verbatim words. Later moments continue that same operator with SendMessage to the agent id the launch result gave (`agentId: …`), carrying the moment, the clock, and the facts — never the brief again; it re-reads before it writes, since the store moved between moments. After the index's `operator-moments:` continuations (four by default) launch it fresh, since every continuation re-sends all it has read and a grown context costs more than a launch; launch it fresh too, and say so, when a continuation fails — the agent gone after a compact or a restart. This context never opens a store file; when a derivation is not enough to steer, it asks the operator for the entry, not the file. A legacy migration is the operator's too. No Agent tool in a session → the degraded path: perform the operation here and say so in the line that reports it.
**The word.** No VLDS operation waits for the user's instruction or permission: the stamp and the row's completion, every append the table names, the pour, the pooled recall, the judged sweep, an attachment's registration, an expiry, the light normalization at the turn's close — each runs in the operator when its trigger fires, and the user is informed, never asked: one line before it runs (what is handed over, and why it is owed) and one line after (what it did, counted) — in the reply, for an operation the operator runs; in the closing that precedes it and the prompt line that follows it, for a hook's. A closing's picker carries no VLDS operation as an option: it ran. What still waits for the per-act word lies outside this layer — version control (commit, push, cache reconcile) and the disposal of anything the user authored — and the pre-write gate's ask is a defect stop, not a permission.
**The clock.** Every `time:` written is copied from the latest `now:` in the hook stream — the SessionStart header, the prompt hook, and every post-write verdict carry one — never guessed; this context hands the operator that `now:` with every message, and a digit no one knows is a defect, not a placeholder.
**The gate.** A `pre-write` hook asks before a store-named file is written outside `store`, a placeholder `time:` is persisted, or a `time:` is persisted later than the latest `now:` by more than a minute — on the operator's writes as on any — and `phi.py check` reports a store-shaped file found outside `store` as `[STRAY]` — re-home it into `store/<name>`; the user disposes of the stray.
**The turn's close.** A `turn-close` hook runs the light normalize sweep after every reply — a hook-poured dispatch record attached where a live segment has room, the virtual entries another session minted expired and poured, the logger's oldest poured past its budget, each step through the register's gates under the sweep lock — and leaves its one-line report for the next prompt hook to print, a Stop hook's own output never reaching the model. Nothing to move: silent. Its context cost is the report line; the context it frees is the next session's recall.

### The shape it takes

```text
class UserMemories {                       // the base: this session's "# Memory" instructions, verbatim
  virtual read()                           //   recall — load MEMORY.md, apply recalled memories to thinking
  virtual write()                          //   persist — one fact per file, plus its MEMORY.md index line
}

class Vlds : UserMemories {                // this layer
  store = <working dir>/.claude/vlds/      // .claude created if absent
  operator = one subagent per session      // hooks/operator-prompt.md — launched at the first moment, continued for the judged moments after, relaunched after operator-moments; returns a derivation
  record   = scripts/record.py             // the close, mechanical: applies the turn's record to store/*, prints the derivation
  override read()  { base.read();  act on operator.open(message).derivation — the barrier's state, the intent, the pool of store/* through the gc read barrier }
  override write() { base.write(); act on record(turn).derivation — what was written to store/* per the table above, the verdict, what is owed }
}
```

If the session carries no base `# Memory` instructions there is nothing to wrap — the overrides still run, with `base.read()` / `base.write()` as no-ops.

**The files.** `store/index.md` and `store/ledger.md` are the guide's; `store/logger.md` the looper's; `store/tombstones.md` the gc's.
The dispatch record is **one file, `store/dispatch.md`**: on a NEW session's first prompt the prompt hook pours it whole-file into `store/arc/` — a byte-identical copy, sha-verified before the reseed, the header preserved — and the dispatcher starts fresh. Every hook output names the session by its short id and its chat title (the title read from the transcript's own title record; the id kept for reference, since a title can change; the `.sessions` ledger maps one to the other); the poured copy is named after the id of the session whose rows it holds. The pour keys on the store's `.sessions` ledger: a resumed conversation's id is already there and pours nothing, a fork's new id is recorded at its SessionStart, and a transient firing never submits a prompt, which is what dissolves the rotation hazard the per-session era was built around. The poured copy sits in `store/arc/` unregistered until a sweep attaches it. The record is never promoted to a rule, and anything worth keeping belongs in `store/logger.md`, which does not expire.
`store/virtual.md`, `store/session-storage.md`, `store/local-storage.md`, and `store/data-store.md` are the gate's storage tiers made literal, written and expired per the table above — no partition invalidates itself, so expiry is lazy, checked at recall, and the gc's to run.
`store/phi-index.md` and `store/arc/` are the gc's φ-register — normalized per its reference whenever the check shows the work owed, the light classes at every turn's close. The index is derived, but a user's edit to it is a ruling — its `## recall` section is where the recall's mode (`pool: subagent | inject`), the models (`operator-model:`, `pool-model:`, `sweep-model:`), the continuation bound (`operator-moments:`), and the read list are chosen. `store/recall-pool.md` is derived too: the operator's pooled response, one per store, named for the session it was pooled for.
One entry shape per file, defined in the file's own header — title, short description, schema prose, and the yaml shape, dispatch-seed style; the owning instrument's reference carries the why, and on divergence the file wins (a user edit is a ruling).

**What this never does.**
It never re-homes, renames, or suppresses base memory files; VLDS files never get MEMORY.md index lines, and base memories never move into `store` — extension, not replacement.
The store stays plain and user-editable; a user's direct edit is a ruling, and the latest ruling wins.
A repo-root `.vlds/` found in the tree is read as a legacy source; new writes land in `store`, its entries are migrated into `store` on first sight — announced before and after, logged — and the legacy directory is left for the user to dispose.

Full procedures: the `vlds` plugin skills — `/vlds:gate`, `/vlds:guide`, `/vlds:gc`, `/vlds:inspector`; the looper surfaces on its own.
